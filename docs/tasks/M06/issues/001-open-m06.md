## Scope

Corporate events restate the quantity of an instrument held, so that transactions
stated under different split conventions accumulate like for like. A datasource
reports splits, reverse splits and stock dividends for a resolved instrument over the
period it was held. An event stores its ratio as an exact from and to. Holdings show an
adjusted quantity where event coverage spans the period an instrument was held, and the
raw quantity elsewhere.

When the system does not apply an event, it stores the event as an unhandled row. The
fetch that met the event reports a finding.

An event that reissues a stable identifier joins the old identifier and the new under
one instrument. A US reverse split issues a new CUSIP and ISIN.

The system compares each split that a statement states with the calendar. It reports a
finding when the calendar lacks the split.

An event references the fetch key that fetched it. An identifier event on a MIC-derived
fetch key invalidates the events on the far side of it. The system refetches those
events.

Out:

- Mergers, spinoffs and other events that change which instrument is held. These are
  stored as unhandled.
- Cash dividends and adjusted prices. These belong with price ingestion.
- Options and the normalisation of OCC symbols.
- Scheduled fetches and the lookahead invariant.
- Retirements implied by corporate events.
- The admin alerts page.
- The per instrument summary of coverage.

## Open questions

- For each provider, starting with Massive and then EODHD:
  - which endpoint reports splits and stock dividends, and what it states for each;
  - whether it takes a stable identifier or only a ticker;
  - whether it states a reissued CUSIP or ISIN;
  - how far back its history reaches, and what the plan allows;
  - its quota, and which of its errors are temporary.
- The primary key of an event, given that one instrument can have several events on a
  day.
- Which event types are applied, and what an unhandled row stores so it can be applied
  later.
- Whether a stable identifier is exclusive on an instrument for all time or on each day,
  once an instrument carries a succession of them.
- What starts a corporate event fetch: the end of a resolution run, an administrator in
  the runs UI, or both.
- How an adjusted quantity is computed for a holding, and how holdings read coverage.
- Which brokers' exports state a split, and in what form. Read `local/originals` and
  each format's specification to answer this.
- How a fractional result of a reverse split is handled, and when the system refuses
  data because a later event could not be applied correctly.
