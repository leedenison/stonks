## Scope

The system fetches end of day prices for the instruments users hold, and values each
holding from them. Each price carries an "as at" date that its datasource client states.
Massive and EODHD each serve prices.

An administrator can also fetch prices and rates through Google Sheets. A command line
tool asks the server for the date ranges that lack a price or a rate. It writes a
GOOGLEFINANCE formula for each range into a spreadsheet. After the spreadsheet has
evaluated the formulas, the tool reads the results and sends them to the server.

The system fetches end of day FX rates. A user selects a display currency, and the
system shows the valuation of each holding in it. The selection starts a fetch of the FX
rates that convert the price currency of each of the user's holdings into the display
currency. The fetch covers the date ranges that lack coverage.

Each rate is stored against USD. A conversion between two other currencies goes through
USD. The fetch for a display currency therefore covers each price currency against USD
and the display currency against USD.

The system shows a period as unknown when it lacks a price or a rate.

A ticker answer is dated by the trading day of its venue. See
[003-venue-trading-day.md](003-venue-trading-day.md).

The Schwab marshaller states each row as at its own date. See
[004-schwab-rows-as-at-own-date.md](004-schwab-rows-as-at-own-date.md).

Out:

- Prices of options, and the option terms they need.
- Corporate actions that retire a listing or change the instrument held.
- Prices and rates a user enters by hand.
- Intraday prices.

## Open questions

Each carries the answer proposed at opening.

- Which datasource serves FX rates. Proposed: Massive and EODHD each serve them where
  the plan on hand has the endpoint, and Google Sheets serves them too.
- Which datasource answers when more than one serves a price for one day. Proposed: the
  datasource precedence decides, as it does for identity. A price from Google Sheets
  ranks below one from Massive or EODHD.
- How the Google Sheets tool signs in to the server and to Google. Proposed: it signs in
  to Google as an administrator through OAuth on the command line. The server accepts
  the Google identity token the tool presents, and requires the administrator role.
- How a GOOGLEFINANCE price states its "as at" date. Proposed: GOOGLEFINANCE serves
  closes adjusted for splits, so each price is as at the day the spreadsheet evaluated
  it.
- Which ticker a GOOGLEFINANCE formula names. Proposed: a ticker that `resolved_tickers`
  places at a venue of the listing, with the venue mapped to the exchange code Google
  uses. An instrument that lacks a mapped venue is skipped and reported.
- Which dates a fetch covers. Proposed: for a price, the days on which any user holds the
  instrument. For a rate, the days on which a user holds an instrument priced in that
  currency.
- Whether the system stores adjusted or as traded prices. Proposed: whichever each
  datasource serves. The system stores each price with its "as at" date. It restates a
  price on read through the corporate actions calendar, as it does a holding.
- What starts a price fetch. Proposed: an administrator starts a system run, and an
  ingest that adds a holding starts a fetch for it. A change of display currency starts
  the FX fetch for that user. The schedule trigger stays in D-RUNS.
- Whether an identifier edge between the date of a price and the time of its fetch
  causes a refetch in this milestone. Proposed: the price references its fetch key, and
  the refetch stays deferred.
- What a failed fetch leaves. Proposed: the stored prices stay, and the days the fetch
  did not cover are shown as unknown.
- What the display currency is before a user selects one. Proposed: USD.
- How a price quoted in a scaled currency such as GBX is valued. Proposed: through the
  scale of its row in `currencies`, as a cash holding is.
- Where the valuation is shown. Proposed: a value column and a total on the holdings
  page, as at the last day that has prices. A valuation history chart is decided when the
  issues are created.
- Whether a price attaches to the instrument or to a listing. Proposed: to the listing,
  since the listing carries the price currency.
