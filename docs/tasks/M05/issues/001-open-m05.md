## Scope

Identifier events bound the interval over which a MIC_TICKER names one instrument.
Massive and EODHD report them. Resolution associates a key through a MIC-derived
identifier only inside its validity, which is confirmed inside event coverage and
provisional outside it. An event that contradicts an association replays the key.

Out:

- Scheduled fetches and scheduled replays. These are a later milestone.
- Implied events, since they are written from corporate events.
- The per instrument summary of validity that holdings and valuation would read.

## Open questions

- For each provider:
  - which endpoint reports identifier events, and what it states for each event;
  - how far back its history reaches;
  - its quota for these endpoints, and which of its errors are temporary.
- How a run records an assumption, so a later event finds every association and fetch
  that rests on it.
- Whether an event replays the keys it affects in the run that recorded it, or records
  them for a replay that an administrator starts.
- Whether the orphan
  [broker-descriptions-in-the-admin-area.md](../../orphans/issues/broker-descriptions-in-the-admin-area.md)
  joins this milestone. When a key's transactions fall in the gap of an inferred event,
  the key resolves through its broker description.
